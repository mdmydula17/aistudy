## 🏗️ 一、 核心架构：两段式解耦设计

系统被拆分为两个互不干扰的模块（对应两套独立的 LangGraph 工作流）：

### 🟢 阶段一：爆款雷达系统 (The Radar Graph)

- **目标**：解决"看什么、买什么"的问题。
- **流程**：输入关键词 → 调用 DrissionPage 在小红书进行列表页搜索 → 提取前 10-20 条高热度元数据（标题、链接、点赞量、作者）→ 存入数据库供前端展示。
- **边界**：**严禁**深入抓取详情页正文，只抓取列表层级的数据！

### 🟣 阶段二：知识炼丹炉系统 (The Synthesizer Graph)

- **目标**：解决"资料融合去重、防止抄袭"的问题。
- **前提**：人类使用者在前端选中雷达任务，并在服务器对应目录（如 `data/local_inputs/{task_id}/`）中放入了花钱买来的高优 PDF / Word / TXT 资料。
- **流程**：读取本地文件夹所有文档 → 并行交由大模型提取为原子知识 (AtomSOP) → 大模型进行 Reduce 融合，去重并重新组织语言 → 输出拥有独立版权的全新 PDF 研报。

## 📝 三、 强制性 Pydantic 数据契约

大模型推理与系统流转，必须 100% 依赖以下 Pydantic V2 模型。

```python
# app/schemas/radar.py
from pydantic import BaseModel, Field

class RadarItem(BaseModel):
    title: str = Field(..., description="笔记标题")
    url: str = Field(..., description="笔记链接")
    author: str = Field(..., description="作者名称")
    likes: str = Field(..., description="点赞数量(支持带有万/w等字符)")

# app/schemas/atom.py
from pydantic import BaseModel, Field
from typing import List

class AtomSOP(BaseModel):
    source: str = Field(..., description="来源文件名标识")
    core_logic: List[str] = Field(..., description="提取出的底层逻辑或干货论点")
    action_steps: List[str] = Field(..., description="具体的操作步骤、话术或套路")

class MasterReport(BaseModel):
    title: str = Field(..., description="重新构思的极具吸引力的商业研报标题")
    markdown_content: str = Field(..., description="逻辑严密、分层清晰的完整 Markdown 正文（绝对禁止照抄原文句式）")
```

## ⚠️ 四、 必须避开的工程"天坑" (代码红线)

1. **LangGraph Reducer 聚合签名**：在定义 State 时，对于需要累加的 List，必须使用标准库的 `operator.add`，禁止自定义签名不明的 merge 函数。
   - ✅ 正确示范：`atoms: Annotated[List[AtomSOP], operator.add]`

2. **LLM 强制结构化输出**：禁止在 nodes.py 中写正则如 `re.search(r"```json...")`。必须调用 LangChain 提供的原生结构化方法：
   - ✅ 正确示范：`structured_llm = llm.with_structured_output(AtomSOP)`

3. **爬虫职责极致精简**：`XiaohongshuCrawler` 只需要实现 `search(keyword: str, limit: int = 10) -> List[dict]`。禁止写任何处理图片或进入详情页的代码。

4. **PDF 渲染降级策略**：优先将最终生成的研报保存为 `.md` 格式。如果需要转 PDF，推荐使用最轻量的方案（如直接调用 markdown 转 HTML，再通过简单的依赖库输出），做好 try-except 兜底，绝不能因为渲染器报错导致任务状态被标记为 failed。

## 🚦 五、 AI 工程师执行协议 (Phase-Driven)

收到人类指令后，按如下阶段（Phase）逐步生成代码，每个 Phase 生成完毕后必须停下来等待人类验收。

- **[Phase 1: 底座搭建]**：生成 models, schemas，并使用 SQLAlchemy 建立 SQLite 数据库，确保 ORM 正确。
- **[Phase 2: 雷达与解析引擎]**：生成 `crawler/xiaohongshu.py` (只写搜索逻辑) 与 `ingestion/local_parser.py` (能读取 TXT/PDF)。
- **[Phase 3: 双轨工作流拼装]**：在 graph 目录下，分别写出 `radar_graph.py` (极为简单，只需 1 个节点) 和 `synth_graph.py` (包含读取本地、转Atom、Reduce融合、保存 4 个节点)。
- **[Phase 4: API 与前端对接]**：暴露给前端 FastAPI 路由。前端仅需展示"雷达监控列表"和"一键开启炼丹"两个核心操作按钮。
